## Failure analysis

None — all assertions passed on this run.

Two failures occurred on earlier runs while stabilizing the flow; both were
**test issues, not app bugs**, and are recorded here so the fixes are not
lost:

1. **`assertVisible: "Beginner"` failed** against label `"Beginner\nTab 1 of 3"`.
   Cause: Maestro matches the *entire* accessibility label as a regex, so a
   bare substring does not match a multi-line label. Fixed with a DOTALL
   regex (`(?s)Beginner.*`). Confidence: high (verified by re-run).
2. **`assertVisible: "DAY 1"` failed** against label `"DAY 1\n0%"`.
   Cause: the grounding dump was captured with Day 1 previously completed
   (label `"DAY 1"`), but the flow runs `clearState: true`, which resets
   progress so the label becomes `"DAY 1\n0%"`. Fixed by (a) using a DOTALL
   regex and (b) re-dumping the hierarchy from cleared state so grounding
   matches run state. Confidence: high (verified by re-run).

## Recommendations

Ordered by priority:

1. **Bake the two selector rules into generation** (fix the test process, not
   this flow): (a) for this Flutter app, match accessibility labels with a
   full-string DOTALL regex when the label carries a suffix; (b) capture the
   grounding hierarchy in the **same state the flow runs in** — for
   `clearState` flows, dump from cleared state. Both are now noted in
   `prompts/generate-flow.md` and `CLAUDE.md`.
2. **No app bugs found.** Home screen renders all expected landmarks on a cold,
   cleared launch. No action for the app team.
3. **Next stories:** extend coverage beyond launch — e.g. selecting a
   difficulty tab, opening a day, and the Journey/Settings tabs — reusing the
   same grounded-selector approach.
